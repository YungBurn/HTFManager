# v0.3.7 Scope Lock

## Milestone name

**v0.3.7 — Portable Profile Bundle & Health**

## Scope statement

v0.3.7 establishes durable profile expected state, read-only health reporting, `.htfbundle` full sharing, profile-first bundle import, and safe restoration of **missing** Mods from bundled artifacts through the existing Package Inspector/install pipeline.

This file exists to prevent later implementation work from accidentally pulling adjacent roadmap items into the release.

## Must ship

1. Profile expectation persistence and v0.3.6 compatibility.
2. Read-only health states: `Healthy`, `Missing`, `VersionMismatch`, `IdentityUncertain`.
3. Export preserves expected metadata rather than current drifted metadata.
4. Lightweight share remains `.htfprofile`.
5. Full share uses `.htfbundle`.
6. `.htfbundle` schema v1 with `bundle.json`, embedded `.htfprofile`, optional payloads, hashes and identity mapping.
7. Minimal retention of eligible HTF-managed source artifacts for future bundling.
8. Full-share eligibility/size summary before export.
9. Profile-first bundle inspection/import with zero automatic package installation.
10. Installed exact matches suppress duplicate installation.
11. Missing + exact bundled payload can enter existing Package Inspector after explicit user action.
12. Missing without bundled payload continues through existing Thunderstore/manual restore behavior.
13. Lazy extraction, path-safety and SHA-256 validation.
14. No direct bundle extraction into the game directory.
15. No automatic Apply after import/restoration.
16. Automated tests for expectations, health, bundle validation/security and recovery planning.

## Detect but do not repair in v0.3.7

`VersionMismatch` is part of health reporting because it is required to avoid destructive duplicate/overwrite behavior during bundle import.

For this release:

```text
Expected 1.2.0
Installed 2.0.0
Bundle contains 1.2.0
```

must result in:

```text
VersionMismatch
No automatic replacement action
```

The bundle payload must not be used as an implicit downgrade/update path.

## Explicitly excluded

The following are **not stretch goals** for v0.3.7:

- version downgrade/upgrade reconciliation for already-installed Mods;
- adopting the currently installed version as a new profile baseline;
- batch/silent `Install All`;
- Nexus integration;
- provider framework rewrite;
- fuzzy package matching;
- dependency-closure bundling;
- automatic loader bundling;
- automatic external/unmanaged Mod bundling;
- reconstruction of package archives from live installed game files;
- persistent caching/import of an entire received bundle;
- bundle signing, trust chains, encryption or passwords;
- strict SemVer compatibility/pinning;
- portable schema v2 without a demonstrated blocker;
- automatic profile Apply.

## Internal implementation checkpoints

### Checkpoint A — Data correctness

Expected metadata survives capture/import/export and legacy migration is conservative.

### Checkpoint B — Health correctness

Health is deterministic, side-effect-free and fully tested.

### Checkpoint C — Bundle correctness

A `.htfbundle` can be written/read safely, identity/hash mappings are deterministic, and malformed archives are rejected.

### Checkpoint D — Export UX

User can choose Lightweight or Full and see what Full can/cannot include before writing.

### Checkpoint E — Import UX

Bundle is inspected profile-first. No package is installed by opening/importing the file.

### Checkpoint F — Missing-Mod restore

Only a missing exact bundled candidate may proceed to existing Package Inspector after explicit user action. Successful installation refreshes/recomputes health.

## Release gate

Do not promote application/version metadata from 0.3.6 to 0.3.7 until all must-ship items pass local Windows/.NET 10 validation and the existing v0.3.6 lightweight profile/Restore Assistant paths remain functional.
