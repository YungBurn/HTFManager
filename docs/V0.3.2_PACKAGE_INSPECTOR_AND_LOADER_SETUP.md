# v0.3.2 — Package Inspector and Loader Setup

## Installation flow

```text
Local ZIP / Local DLL / Thunderstore
                |
                v
       Package Inspector
                |
        +-------+-------+
        |               |
 missing loader     loader ready
        |               |
        v               |
 Loader Setup            |
        |               |
        +-------+-------+
                v
        dependency check
                |
                v
       existing conflict check
                |
                v
           staging
                |
                v
        transactional install
                |
                v
           ownership
```

## Package risk rules

- `Safe`: valid package, required loader is ready, no conflicts, no warnings.
- `Warning`: valid package with inferred metadata, update state, missing loader, or other non-fatal warnings.
- `Blocked`: invalid package or target-file conflict.

A missing loader is intentionally treated as a recoverable warning: installation stays disabled until Loader Setup succeeds and the package is re-inspected.

## Loader setup sources

### BepInEx

Recommended package: `BepInEx-BepInExPack-5.4.2305` from Thunderstore.

Expected content root contains:

```text
BepInEx/
winhttp.dll
doorstop_config.ini
```

### MelonLoader

Source: official `LavaGang/MelonLoader` GitHub Releases. The installer queries the latest release, chooses a Windows x64 ZIP, then validates that the extracted content root contains:

```text
MelonLoader/
version.dll
dobby.dll
```

## Ownership boundary

Loader files are not stored in the normal mod `installations.json`. They are tracked separately in:

```text
%LOCALAPPDATA%\HTFManager\loaders\installations.json
```

This prevents loader lifecycle operations from being confused with normal mod lifecycle operations.

Loader uninstall removes only tracked loader files. It does not intentionally own or delete:

```text
BepInEx/plugins
BepInEx user-generated config
Mods
Plugins
UserData
```

## Existing external loader

If BepInEx or MelonLoader is already present but has no HTF Manager loader record, it is displayed as an external installation. Automatic repair/update/uninstall is disabled rather than silently taking ownership or overwriting unknown bootstrap files.
