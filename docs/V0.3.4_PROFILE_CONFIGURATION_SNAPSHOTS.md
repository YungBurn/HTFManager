# v0.3.4 Profile Configuration Snapshots

## Goal

Profiles should describe a reproducible How to Fish Mod environment rather than only a list of DLL enable states.

A profile therefore consists of two independent layers:

```text
Profile
├─ ModStates
│  ├─ Mod A = enabled
│  ├─ Mod B = disabled
│  └─ ...
└─ ConfigurationSnapshots (optional)
   ├─ Mod A config
   ├─ Mod C config
   └─ ...
```

Removing a Mod from a profile never uninstalls it. Clearing a configuration snapshot never deletes the live configuration file.

## Snapshot scope

Only `ModConfigurationDocument` entries that:

- are associated with a Mod contained in the profile;
- are not Loader configuration documents;
- exist inside the detected game directory;

are captured.

`BepInEx.cfg` and MelonLoader `Loader.cfg` are deliberately excluded because they affect the entire loader environment, not one profile's Mod behavior.

## Storage

Profile metadata stays in:

```text
%LOCALAPPDATA%\HTFManager\profiles\<profile>.json
```

Snapshot bytes are separate:

```text
%LOCALAPPDATA%\HTFManager\profile-snapshots\<profile>\
```

Each snapshot record stores:

- relative target path from the game root;
- Loader kind;
- associated Mod ID;
- SHA-256 hash;
- capture time;
- local snapshot filename.

No absolute game path is persisted in snapshot metadata, so moving the Steam library does not invalidate the profile by itself.

## Apply transaction

Before applying snapshot files, HTF Manager verifies that every source snapshot exists and matches its stored SHA-256 hash.

The current destination configuration files are copied into:

```text
%LOCALAPPDATA%\HTFManager\profile-recovery\<profile>\<timestamp>\
```

The manager then applies Mod states and copies configuration snapshots. If a later step fails, files are restored from the recovery directory and changed Mod states are rolled back where possible.

A snapshot whose associated Mod is no longer contained in the profile is retained in metadata but skipped during apply. The UI marks this condition and the next **Update snapshot** operation removes stale entries by rebuilding the snapshot from the current profile membership.

## Unsaved Configuration Center edits

Saving a profile with a configuration snapshot, updating an existing snapshot, or applying a profile is blocked while any configuration document has unsaved edits in memory. This prevents a disk snapshot operation from silently discarding edits the user has not saved or reverted.

## UI constraints

The existing collapsible profile design is retained.

- profile list remains fixed-height and scrollable;
- the Mod membership list remains fixed-height;
- the configuration snapshot list is a separate fixed-height scroll area;
- collapsed profile cards remain concise.
