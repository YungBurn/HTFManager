# HTF Manager v0.3.0 — Multi-loader foundation and profile editor

## Scope

v0.3.0 turns the environment model from a BepInEx-only model into a loader-aware model while preserving all v0.2 Thunderstore and BepInEx package-management behavior.

This release **detects and manages already-installed MelonLoader Mods/Plugins**, but intentionally does not install, update, uninstall, or bootstrap-switch MelonLoader itself yet. It also does not route downloaded ZIP/DLL packages into MelonLoader yet; that remains the next package-installer step.

## Loader model

The game environment now contains two independent loader environments:

- `BepInExEnvironmentInfo`
  - root, plugins, patchers, config, log, bootstrap and version;
- `MelonLoaderEnvironmentInfo`
  - root, Mods, Plugins, UserData, Loader.cfg, Logs, version.dll, dobby.dll and version.

`GameEnvironmentInfo` retains compatibility aliases (`BepInExFound`, `PluginsDirectory`, etc.) so the existing v0.2 package installer and Discover code do not need a risky rewrite in the same patch.

## Mod scan model

`InstalledMod` now records:

- `Loader`: Unknown / BepInEx / MelonLoader;
- `Component`: Plugin / Mod / Patcher / Content / Library / Modpack.

The scanner aggregates:

- `BepInEx/plugins/**`;
- `BepInEx/patchers/**`;
- `Mods/**` (MelonLoader mods);
- `Plugins/**` (MelonLoader plugins);
- HTF Manager ownership records.

Existing BepInEx external IDs remain compatible with v0.2 profiles. MelonLoader external IDs use separate prefixes to prevent collisions.

## Enable / disable

Both loaders use file-level enable state for scanned DLL components:

```text
SomeMod.dll
<->
SomeMod.dll.disabled
```

HTF Manager still blocks these changes while How to Fish is running.

This release does **not** disable or rename `version.dll` / `winhttp.dll`; loader bootstrap switching is deliberately outside v0.3.0.

## Profiles redesign

Profiles are now treated as isolated mod sets rather than only a loose snapshot of known states.

When a profile is applied:

- mods included in the profile are set to their stored enabled/disabled state;
- installed mods not included in the profile are disabled;
- no mod is uninstalled or deleted.

The profile page is split into two fixed-height areas:

1. a scrollable profile selector;
2. a fixed-height profile detail/editor with its own scrollable mod list.

This prevents large profiles from stretching the page.

### Profile editing

For the selected profile users can:

- apply it;
- delete the profile file;
- add an already installed mod;
- remove a mod from the profile without uninstalling it;
- choose whether each included mod should be enabled or disabled when the profile is applied.

Removing a mod from a profile only edits the profile JSON. The mod remains installed on disk and in the global Mods page.

## Right panel

The persistent right panel now reports both loaders and adds loader-specific quick actions when their directories exist:

- Open BepInEx Mods;
- Open MelonLoader Mods;
- Open MelonLoader Plugins;
- View BepInEx log;
- Open MelonLoader Logs.

## Tools

Tools now has side-by-side BepInEx and MelonLoader cards and loader-aware diagnostics.

## Compatibility and migration

No migration command is required.

Existing files under `%LOCALAPPDATA%\\HTFManager` are retained. Existing profile JSON continues to load because `ModStates` is unchanged. Existing managed installation records also load; loader/component values that do not exist in older records are inferred from owned file paths at scan time.

## Intentional limitations

v0.3.0 does not yet:

- install MelonLoader itself;
- switch between BepInEx / MelonLoader / Vanilla bootstrap modes;
- import a local MelonLoader ZIP/DLL into `Mods/` or `Plugins/`;
- download from Nexus;
- edit `UserData/Loader.cfg` or `MelonPreferences.cfg`.

Those features can now be added without changing the core environment model again.
